# 11.14 分层深度探索协议：推导任务的检索策略

**编号**：11.14
**日期**：260821
**系列**：总结与哲学
**语言**：CN

## 背景：推导任务的检索深度问题

在推导未知问题的过程中，检索系统的默认行为是"问答模式"：一次向量查询、命中若干片段、注入上下文、开始回答。这一模式适用于"某篇文章讲了什么"类问题，但对于推导任务存在系统性缺陷：

1. **单轮查询的信息壁垒**：一次查询只能覆盖一个语义角度，而推导需要的是知识地图——相关定理、证明依赖、跨文章连接。
2. **命中即止的放弃机制**：首轮查询未命中时，默认反应是"库中没有"或硬推，而不是换角度、追引用、查目录。
3. **注入截断**：上下文仅注入约 5-8 块，推导所需的结构（定理+证明+依赖+应用）分散在多篇文章中，单次注入装不下。

观察到的现象：对未知问题的推导，检索深度不足，容易放弃。本文提出分层深度探索协议作为推导类任务的标准检索策略。

## 核心洞察：覆盖完备性

推导 = 在信息场中建立覆盖，然后在覆盖的结构上生成。单次检索是**点覆盖**（照亮一个点）；深度探索是**面覆盖**（系统照亮整片地形）。检索未命中不等于信息不存在——那是**覆盖策略失败**。

框架内表述：11.11 的试错累积图景指出，检索失败是一次试错，正确反应是换路径，不是停步。C-11 的注入循环（注入→吸收→推进）同样要求充分的注入才有扎实的推进。

**成本洞察**：浅推的返工成本高于深推的一次到位。浅推省下的 token 换不来核心文章，换来的是错误或残缺的结论——返工 ≥2.3 轮时深推反而更便宜。

## 三层结构

| 层 | 触发场景 | 流程 | token 预算 | 覆盖目标 |
|---|---|---|---|---|
| L0 轻量 | 事实查询、日常问答（`_is_simple` 命中） | 单轮检索 → 回答 | ≤5k | top5 命中 |
| L1 标准 | 普通主题讨论、文章内容询问 | 1-2 次检索 + 可选核实 | ≤15k | top5 命中 |
| L2 深度 | 推导/证明/验证/审核/综合/猜想 | 六步协议 | ≤20k（工具化后 ≤10k） | 推导链 100% 支撑 |

分层原则：该花的花，不该花的不花。日常问答走轻量路径（零增量），推导类任务才触发深度协议。

## L2 触发条件（任一命中即进入）

1. **显式动词**：推导、证明、验证、审核、深挖、探索、综合、对照文章
2. **结构标记**："为什么 X"、"X 如何成立"、"X 的机制"、"X 的完整链条"
3. **用户要求**：查深一点、挖掘可能性、估计收益、对照原文
4. **任务特性**：跨 3+ 主题、需要依赖链、开放猜想

## L2 六步协议（省 token 版）

| 步 | 动作 | 输出 | token |
|---|---|---|---|
| S0 | **声明**：一句话声明"进入 L2，目标 X，拆解 N 个子问题" | 声明 | 0.2k |
| S1 | **拆解**：子问题清单（编号，不展开） | 清单 | 0.3k |
| S2 | **两阶段查询**：每子问题先 1 角度宽查（并行发）；缺口子问题才补 2-3 角度 | 命中记录 | 6-10 次检索 |
| S3 | **聚合**：按文章编号聚合（内部），输出编号+标题+命中数 | 文章清单 | 1k |
| S4 | **精准核实**：仅 2-3 篇核心文章的定理段落（section 跳转，不读全文） | 结构摘录 | 每篇 ≤2k |
| S5 | **引用链**：优先引用图（0.5k/跳）；无图则 1-2 次定向检索 | 依赖链 | 1-2k |
| S6 | **缺口 + 探索地图**：树形地图 + 缺口清单 + 诚实标注 | 地图 | 1k |

预算合计 12-20k token。省 token 的四个杠杆：两阶段查询（不每子问题都多角度）、精准 section 跳转（不读全文）、引用图（只返回编号+关系，不返回全文片段）、探索记录复用（同主题第二次 ≈0）。

## 质量守则

1. **未命中 ≠ 不存在**：换角度 → 查引用 → 查文章列表 → 查目录 → 才允许标注缺失。
2. **支撑分级**：定理原文（强）> 向量命中/摘要（中）> 相关主题（弱）——推导只引用强/中支撑。
3. **缺口必须显式报告**：不掩盖、不硬编、不假装闭环。
4. **每次 L2 必须给出探索地图**——这是检查深度的手段，也是推导的责任清单。

## 验证：α⁻¹ = 137.036 几何来源案例

2026-08-21 实测对照：

| 维度 | 对照组（1 次检索） | 六步协议（10 检索 + 2 原文核实） |
|---|---|---|
| 覆盖文章 | 11 篇 | 51 篇（4.6 倍） |
| 推导链核心支撑 | 1/8（仅 1.5） | 8/8（100%） |
| 引用链深度 | 0 跳 | 2 跳 |
| 能否回答"137 从哪来" | 不能（缺 2.4/0.8/7.5） | 能给出完整机制链 |
| 挖出的新缺口 | 0 | 3 |

对照组遗漏的核心文章：2.4（谱条件来源与定理 2.4.4.01）、0.8（a₄ 锁定 α）、7.5（σ* 定义）、2.1（Cramer 组合）、9.6（S_e 锚定）、10.39（质量角）、10.25（θ13）——**7 篇推导链核心**。对照组的浅推会直接得出错误结论："137 是观测者位置输入、不可推导"，而实际上 0.8 有 a₄ 锁定、2.4 有谱展开机制，推导链是存在的。

协议挖出的新缺口（对照组根本不知道要问）：
1. T_ours (0.782, 0.209, 0.009) → σ* (0.777912, 0.210603, 0.011484) 的精化机制位置
2. 0.8 中 α 是输入（反解 Λ）与 2.4 谱展开推出 S=137.036 之间的张力
3. Cubic-Born 架构的文章位置

成本核算：单次深度探索约 20k token（≈¥0.04），引用图工具化后 8-10k。浅推返工 ≥2.3 轮即比深推更贵。

## 探索记录机制

每次 L2 结束，把探索地图写入探索日志（个人数据库）：

```
【探索地图】目标: α⁻¹=137.036 的几何来源
├─ 谱条件   → 1.5, 2.4 ✓   (2.4 定理 2.4.4.01 = T_ours 源头)
├─ σ*       → 7.5, 2.4§4.1 ✓ (精化机制: 待查 Cubic-Born)
├─ 作用量   → 1.5, 0.8 ✓   (a₄ 锁定 α)
├─ 常数组合 → 2.1 ✓         (Cramer)
└─ 锚定     → 9.6, 10.39, 10.25 ✓
缺口: ① T_ours→σ* 精化 ② 0.8 α输入 vs 2.4 谱展开 ③ Cubic-Born 位置
```

同主题第二次探索直接复用地图，只追新缺口——探索记录既是 token 节省，也是知识地图的增量积累。

## 工具化展望：引用图

六步协议手工执行约 12 次调用。引用图工具化后："2.4 → 2.3.7 → 圆满再现"类跳转 1 次查询完成，探索效率提升一个量级且不漏链。引用图 = 扫描全文提取"文章 X.Y / 定理 Z"引用格式，构建有向图，推导时沿图遍历——把检索从"语义相似"升级为"结构关联"。

## 与框架的联系

- **11.11 试错累积**：检索失败 = 试错，换路径是自然反应；推导是在给定累积结构下筛选。
- **C-11 注入循环**：充分的注入（深度探索）→ 充分的吸收（原文核实）→ 扎实的推进（有支撑的推导）。
- **信息场覆盖**：L2 的目标是覆盖完备性——推导所需结构全部被照亮后才动笔。

## 执行纪律

凡推导类任务，先声明进入 L2，走完六步才动笔；未走完协议不许说"库里没有"。
