# 计算三行制规范（2026-08-21 立）

## 原则

语言模型的计算是 token 预测，不是算术。单步错误率是机制性的，不随"仔细程度"改变。
减少计算错误的唯一有效途径：**减少模型承担的计算量**。
模型只做两件事：写表达式、解释结果。执行交给工具。

## 三行制格式

每次数值计算固定格式：

```
表达式：<公式>，<输入及来源行号>，<预期数量级>
执行：[shell python 一次完成：正向 + 反向验证 + 标度断言 + 单位代数]
结果：<数值>（断言通过/失败）
```

## 六条机制

1. **计算外包**：所有数值计算写 python，shell 执行，不展开中间步骤
2. **符号先行**：推导全程符号化（α⁻¹、χ_L、δ₀…），数值只在最后一步代入
3. **三重检查**：一个脚本内完成 正向 + 反向 + 标度断言
4. **单位随行**：量纲作为符号参与计算（工具自动检查，非模型自检）
5. **数值取原文**：常数从文章/基准卡 grep 取值，不凭记忆
6. **标度预检**：表达式前写预期数量级，脚本内 assert

## Token 分析

| 项 | 成本 |
|---|---|
| 写表达式 | ~100 token |
| 展开手算（逐步） | 500-2000 token |
| 三重检查（脚本内+3行） | ~50 token |
| 错误返工 | 10 倍以上 |
| 净效果 | token 不增反减，错误率从"模型机制性错误率"降到"python 执行错误率≈0" |

## 错误类型覆盖

- 大数幂/指数荒谬值（10³⁸ 类）→ 标度断言 + 工具执行
- 多步链式中间值漂移 → 变量链（模型不记忆中间值）
- 量纲/单位混用（微观标度当宏观量）→ 单位符号代数
- 常数记忆错误 → grep 原文取值
- 因子错误（δ_BL vs δ₀）→ 教学反馈 + 符号化推导（此类是公式错误非计算错误，但符号化能暴露）
