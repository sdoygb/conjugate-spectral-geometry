Radeon RX 570 8G — GPU 辅助中间层可行性原型验证

设备 AMD Radeon RX 570 Compute Engine · 8.6 GB 显存 · 32 CU · Metal/OpenCL · 2026-08-21

结论先行

用 OpenCL（Apple 驱动直抵 570）编写了标准 GPU 分块共享内存矩阵乘内核，与 CPU numpy（MKL 优化）做全对全相似度矩阵（A·Aᵀ，即「多对多交叉验证」的核心计算）的逐规模实测。 结论：你当前的数据规模（全库 3444 段 × 1024 维）刚好处在 GPU 收益的临界点之下 —— GPU 与 CPU 基本打平。预计跨过约 4096×1024 的量级后，GPU 纯算力开始稳定反超。

两种解读

别急着改造

你现在的中间层只需一次全对全 = CPU 0.09 秒，GPU 没便宜可占。为集成 GPU 增加的复杂度（数据搬移、同步、显存管理）反而会拖慢小规模任务。当前规模下，升级检索算法（多跳/超图）比升级硬件收益大得多。

何时该上 GPU

当你的交叉验证规模突破几千×几千、且把整块任务一次性驻留显存（反复复用 embedding 矩阵，避免每次搬移）时，GPU 开始稳定领先。典型场景：全库段与段的全对全、多目标 × 全库的大批量 pairwise。

关于你的核心诉求「关系多对多、错综复杂的推理」

实验进一步印证了最初的判断：「让 GPU 去遍历/承载那幅多对多关系网」是用错了对象。 关系网的稀疏遍历、逐段判断是 CPU 的天职，GPU 派不上用场，反而更慢。 GPU 真正、唯一值得吃的，是把「N×M 对候选关系」一次性铺开成矩阵做批量相似度/冲突检测 —— 这才是 GPU 的果实，也才是把现有多对多交叉验证从「LLM 逐句问」升级为「一次算完、整网铺开」的可行路径。Radeon 内核已跑通可用于此。
