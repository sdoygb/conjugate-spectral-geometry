## 摘　要

10.87 §6 提出的离散动态演化方案（top-k 空间收缩 + 幂迭代 + 稀疏 H·v）将 H₂O cc-pVDZ 从"353 天不可行"降到"数小时可行"，但存在三个根本缺陷：① **幂迭代无 shift 时收敛到绝对值最大本征值（不一定是基态）**——合成系统实测收敛到 -18.67 Ha 而非基态 -13.70 Ha；② **top-k 截断是无结构的幅值选择**，丢弃的可能是几何上关键的低幅值连接态；③ **k 的选择缺乏几何指导**（10.87 实测 k/dim ~ 0.13-1.5%，但这是经验标度而非定理）。

本文基于 10.87 §6.03 证实的**波包模型**（基态 = Grassmann 流形上少数局部波包的叠加，单参考 1 个、多参考 3-5 个），推导并实现**波包组态交互（Wavepacket Configuration Interaction, WCI）**：

1. **波包 = 中心行列式 + Bruhat 2-邻域**（通过 H·中心生成所有 1-2 激发目标，含两体对角）。每个波包的支撑集是 Bruhat 图上的连通球，半径由哈密顿量的体数（1-2 体）决定——**物理预算，不可压缩但有结构**。
2. **变分空间 = 所有波包支撑集的并集**（累积增长，Bruhat 连通）。每轮在变分空间内构造稠密 H 矩阵 → Rayleigh-Ritz 对角化 → 残差 r = H|ψ⟩ - E|ψ⟩ → **新波包中心 = 变分空间外残差最大的行列式**。
3. **变分原理保证单调收敛**：E_{k+1} ≤ E_k（Rayleigh-Ritz 下界），且每轮严格添加新方向 → 收敛到变分空间内的精确基态。**无 top-k 幂迭代的"收敛到错误态"风险**。
4. **四分子系统实测验证波包数 1-6 个**（化学精度）：H₂/STO-3G（dim=4）1 个、LiH/STO-3G（dim=225）4 个、H₂O/STO-3G（dim=441）6 个、LiH/6-31G（dim=3025）化学精度 10 个（精确收敛 28 个、重跑 29 个，后 18 个仅修正最后 4.0e-7 Ha）。**波包数随 dim 亚线性增长（∝ log dim）；top-k 的 k 依 10.87 §6.02 实测同为亚线性（k/dim 随规模下降：1.5%→0.13%），非线性——但波包数（≤10）远小于 top-k 的 k（10³ 量级）**。
5. **三层性能优化**：① np.searchsorted 代替字典查找（H 填充 +17%）；② 增量 H 矩阵构造（每轮只对新增态做 apply，旧块复用——第 28 轮 H 构造 1.9s→0.025s，77 倍）；③ float64 代替 complex128（实基组积分实数，eigh 对实对称矩阵快 17 倍）。**LiH/6-31G 总时间 175s→44s（4 倍），H 矩阵构造 9.8s→0.4s（24.5 倍）**。

**诚实边界**：① WCI 是变分截断 CI（非完整 FCI），波包数由残差驱动自适应选择；② 波包数 1-6 个的结论在 STO-3G 小基组下精确成立，6-31G 更大基组下化学精度需 10 个波包（更多相关通道），NO 基变换（10.87 §6.05 验证 eff-dim 降 289 倍）预计可进一步压缩；③ 当前实现瓶颈已从 H 矩阵构造转移到残差计算（全空间 apply_H，占 ~75% 时间），增量残差是下一步优化方向。

## §1　问题：top-k 幂迭代的三个根本缺陷

### §1.1　10.87 方案回顾

10.87 §6 提出的离散动态演化方案由三部分组成：

1. **top-k 空间收缩**：从全空间 dim 中选取幅值最大的 k 个行列式（k/dim ~ 0.13-1.5%），构造 k 维子空间；
2. **幂迭代**：在 k 维子空间内做 H·v 幂迭代 ~200 次收敛；
3. **稀疏 H·v**：只访问 v 非零行，O(k × 行度)。

该方案将 H₂O cc-pVDZ 从"353 天不可行"降到"数小时可行"，是几何化管线的重要工程突破。

### §1.2　缺陷一：幂迭代的本征值歧义

**命题 10.88.1.01（幂迭代收敛目标，定理）**。无 shift 的幂迭代 v_{n+1} = H v_n / ||H v_n|| 收敛到 H 的**绝对值最大**本征值对应的本征向量，而非**代数最小**本征值（基态）。当哈密顿量存在负本征值且绝对值最大本征值不是基态时，幂迭代收敛到激发态。

**证明**。设 H 的本征值为 {λ_i}，按绝对值排序 |λ_1| ≥ |λ_2| ≥ ...。初始向量 v_0 = Σ c_i |i⟩，则 v_n = H^n v_0 / ||...|| = Σ c_i λ_i^n |i⟩ / ||...||。当 n→∞，|λ_1/λ_i|^n → 0（i > 1），故 v_n → |1⟩（绝对值最大本征向量）。若 λ_1 > 0 但基态 λ_0 < 0 且 |λ_0| < λ_1，则幂迭代收敛到激发态 |1⟩ 而非基态 |0⟩。∎

**验证 10.88.1.02（合成系统实测，机器验证）**。在 n_orb=6, nelec=6（dim=400）的随机积分合成系统上：

- top-k 幂迭代（k=400 全空间，500 次迭代）：收敛到 **E = -18.67 Ha**
- 精确 FCI（np.linalg.eigh 全对角化）：基态 **E = -13.70 Ha**
- 误差：**4.97 Ha**（差化学精度 3 个数量级）

幂迭代收敛到了绝对值最大的本征值（-18.67，绝对值 18.67），而非代数最小的基态（-13.70）。**这是 top-k 幂迭代的根本性缺陷，无法通过增加 k 或迭代次数解决**——除非添加 shift（E_shift = E - σI，使基态成为绝对值最大），但 σ 的最优选择依赖基态能量本身（循环依赖）。

**调和 10.87 的实测结果（为何 10.87 §6 的 top-k 在真实分子上仍达到化学精度）**。本缺陷与 10.87 §6 的机器验证结果不矛盾：那些分子的**基态恰好是 |λ| 最大本征态**——基态能量 |E₀|（LiH ≈ 8 Ha、H₂O ≈ 75 Ha、N₂ 6-31G fc ≈ 109 Ha）远超最正本征值的可能量级（受虚轨道能标约束，通常至多几十 Ha），因此"绝对值最大"本征向量就是基态。§1.2 的合成系统用**随机积分**破坏了这一谱性质（随机矩阵谱散布大，正本征值可超过 |E₀|），幂迭代缺陷才暴露。结论：top-k 幂迭代在"基态为 |λ| 最大"的谱条件下可用（10.87 实测即此情形），但**该条件无一般保证**；WCI 的变分路线（§3-4）不需要任何谱条件。

### §1.3　缺陷二：top-k 截断的无结构性

**命题 10.88.1.03（top-k 截断的几何盲目性，结构命题）**。top-k 截断按 |c_D| 幅值选择行列式，丢弃的是低幅值态。但 10.87 §6.03 证实基态是**少数波包的叠加**，每个波包的支撑集是 Bruhat 连通球——波包边缘的态可能幅值很低但几何上关键（连接两个波包的桥梁态）。top-k 截断可能丢弃这些桥梁态，导致变分空间不连通，残差无法有效驱动后续迭代。

**对比**：WCI 的变分空间是波包支撑集的并集，天然保持 Bruhat 连通性——每个波包内部是连通球，波包之间通过残差驱动添加新波包中心（必然与已有空间有 H 连接，否则残差为零）。

### §1.4　缺陷三：k 的选择缺乏几何指导

10.87 实测 k/dim ~ 0.13-1.5%（小系统 1.5%，大系统 0.13%），但这是**经验标度**而非定理。k 太小则截断误差大，k 太大则浪费计算。没有几何原理告诉我们"这个系统需要多少个态"。

WCI 用**残差驱动的自适应波包添加**代替固定 k：每轮计算残差 r_out = ||P_{⊥} H|ψ⟩||，若 r_out > tol 则添加一个新波包（中心 = 残差最大的行列式），直到 r_out < tol。**波包数由系统的相关结构自动决定，无需人工选择 k**。

## §2　几何论基础：波包模型与 Bruhat 邻域

### §2.1　行列式空间的 Bruhat 图

**定义 10.88.2.01（Bruhat 距离）**。两个斯莱特行列式 |D⟩, |D'⟩ 的 Bruhat 距离 d_B(D, D') = 它们占据自旋轨道集合的对称差大小的一半。即若 |D⟩ 占据轨道集 A，|D'⟩ 占据 A'，则 d_B = |A △ A'| / 2。

- d_B = 0：同一行列式
- d_B = 1：单激发（一个轨道替换）
- d_B = 2：双激发（两个轨道替换）

**定义 10.88.2.02（Bruhat 图）**。顶点 = 所有行列式（固定 N, S_z），边 = d_B = 1 的行列式对。Bruhat 图是正则图，度数 = 单激发数 = 2·n_α·(n_orb - n_α) + 2·n_β·(n_orb - n_β)（S_z=0 时 n_α=n_β）。

### §2.2　1-2 体哈密顿量的 Bruhat 局部性

**命题 10.88.2.03（H 的 Bruhat 局部性，定理）**。1-2 体哈密顿量 H = Σ h_pq a_p^†a_q + (1/2)Σ V_pqrs a_p^†a_q^†a_sa_r 连接两个行列式当且仅当 d_B(D, D') ≤ 2。

**证明**。单体算符 a_p^†a_q 湮灭一个轨道 q 并创建一个轨道 p，改变占据集合同样差大小 = 2 → d_B = 1。两体算符 a_p^†a_q^†a_sa_r 湮灭两个轨道 (r,s) 并创建两个 (p,q)，对称差大小 = 4 → d_B = 2（若 p,q 中有与 r,s 重合的则 d_B < 2，对应两体对角或单体有效项）。因此 H 的非零矩阵元仅存在于 d_B ≤ 2 的行列式对之间。∎

**推论 10.88.2.04（H·v 的行度）**。H|D⟩ 的非零目标数 = Bruhat 2-邻域大小 = 单激发数 + 双激发数（含两体对角）。对 H₂O cc-pVDZ（n_orb=19, n_α=n_β=5）：每行 6860 个非零（10.87 §1 实测）——**组合必然，物理预算**。

### §2.3　波包的几何定义

**定义 10.88.2.05（波包，Wavepacket）**。以行列式 |D_c⟩ 为中心的波包 W(D_c) = { |D⟩ : d_B(D, D_c) ≤ 2 }，即 Bruhat 图上以 D_c 为中心、半径 2 的闭球。

**命题 10.88.2.06（波包 = H·中心的支撑集，定理）**。波包 W(D_c) 的支撑集恰好是 H|D_c⟩ 的非零目标集（含 D_c 自身，对应对角元）。

**证明**。由命题 10.88.2.03，H|D_c⟩ 的非零目标满足 d_B(D, D_c) ≤ 2，即 D ∈ W(D_c)。反之，对任意 D ∈ W(D_c)（d_B ≤ 2），存在 1-2 体算符项连接 D_c 和 D，一般位置下 ⟨D|H|D_c⟩ ≠ 0。因此 **supp(H|D_c⟩) ⊆ W(D_c)**——Bruhat 2-球是支撑集的上界。注意：对称分子中大量耦合被对称性**精确**清零，支撑集是过滤后的子球。本文 §6 实测：LiH/STO-3G 首波包 35 态 / 组合行度 93（62% 精确为零）、LiH/6-31G 191/433（56%）、H₂O/STO-3G 49/141（65%）——对称性过滤使波包更小，对 WCI 有利。∎

**意义**：波包不是人为定义的截断，而是哈密顿量 Bruhat 局部性的几何必然——H·中心自然生成 Bruhat 2-球（或其对称性过滤子集）。

### §2.4　10.87 §6.03 的波包模型

**验证 10.88.2.07（基态 = 少数波包叠加，10.87 §6.03 实测）**。10.87 在 cc-pVDZ 级分子上证实：

- **单参考系统**（基态接近 HF）：基态 = **1 个波包**的主导叠加（HF 中心 + 其 Bruhat 2-邻域），HF% > 95%；
- **多参考系统**（解离、开壳层）：基态 = **3-5 个波包**的叠加，每个波包中心对应一个重要组态（如 HF、关键双激发、近简并组态）；
- **波包连续表示 = RS-1 微扰谱**（10.87 §6.04）：c_D ≈ -H_DF / ΔE_D，单参考系统 corr = 0.957；
- **NO 基使波包坍缩 289 倍**（10.87 §6.05）：自然轨道基下 eff-dim 从 289 降到 1。

WCI 算法正是这一波包模型的**算法化实现**：不再用无结构的 top-k 截断，而是直接构造波包并在波包空间内做变分对角化。

## §3　WCI 算法推导

### §3.1　算法框架

**定义 10.88.3.01（WCI 算法）**。给定哈密顿量 H（1-2 体，matrix-free 接口 apply）、初始种子行列式 |D_0⟩（通常为 HF 态）、收敛阈值 tol：

1. **初始化**：波包列表 𝒲 = [W(D_0)]，变分空间 𝒱 = supp(W(D_0))
2. **迭代**（直到收敛或达到最大波包数）：
   a. **Rayleigh-Ritz**：在 𝒱 内构造稠密 H 矩阵 H_𝒱，对角化得最低本征值 E 和本征向量 |ψ⟩ = Σ_{D∈𝒱} c_D |D⟩
   b. **残差计算**：r = H|ψ⟩ - E|ψ⟩，分解为空间内分量 r_in = P_𝒱 r 和空间外分量 r_out = P_{⊥} r
   c. **收敛判据**：若 ||r_out|| < tol 且 |E - E_prev| < tol，停止
   d. **新波包**：新中心 D_new = argmax_{D∉𝒱} |⟨D|r⟩|（简化判据；能量最优的加权判据见命题 3.03 与推论 3.04），添加 W(D_new) 到 𝒲，更新 𝒱 = 𝒱 ∪ supp(W(D_new))
3. **输出**：E, |ψ⟩, 波包数 |𝒲|, 变分空间大小 |𝒱|

### §3.2　Rayleigh-Ritz 变分原理

**命题 10.88.3.02（Rayleigh-Ritz，定理）**。设 𝒱 是希尔伯特空间 ℋ 的有限维子空间，H 是 ℋ 上的自伴算符。定义 H_𝒱 = P_𝒱 H P_𝒱（𝒱 内的矩阵表示），其最低本征值为 E_𝒱。则：

1. **变分下界**：E_𝒱 ≥ E_0（E_0 为 H 的精确基态能量）；
2. **单调性**：若 𝒱 ⊆ 𝒱'，则 E_𝒱' ≤ E_𝒱（子空间越大，下界越紧）；
3. **本征向量**：E_𝒱 对应的本征向量 |ψ_𝒱⟩ ∈ 𝒱 满足 ⟨ψ_𝒱|H|ψ_𝒱⟩ = E_𝒱。

**证明**。(1) 对任意 |ψ⟩ ∈ 𝒱，⟨ψ|H|ψ⟩ ≥ E_0（变分原理），故 min_{|ψ⟩∈𝒱} ⟨ψ|H|ψ⟩/⟨ψ|ψ⟩ ≥ E_0。(2) 𝒱 ⊆ 𝒱' → min 在更大集合上取 → E_𝒱' ≤ E_𝒱。(3) 由自伴算符的谱定理。∎

### §3.3　残差驱动的波包添加

**命题 10.88.3.03（残差的最优修正方向，定理）**。设 |ψ_𝒱⟩ 是 𝒱 内的 Rayleigh-Ritz 基态近似，E_𝒱 = ⟨ψ_𝒱|H|ψ_𝒱⟩。残差 r = H|ψ_𝒱⟩ - E_𝒱|ψ_𝒱⟩。若添加一个新方向 |D_new⟩ ∉ 𝒱 到变分空间，则能量修正的一阶近似为：

ΔE ≈ - |⟨D_new|r⟩|² / (⟨D_new|H|D_new⟩ - E_𝒱)     （⟨D_new|ψ_𝒱⟩ = 0，因 D_new ∉ 𝒱 而 |ψ_𝒱⟩ ∈ 𝒱）

**证明**。这是标准的 RS-1 微扰理论（或 Davidson 校正）。设新空间 𝒱' = 𝒱 ⊕ span{|D_new⟩}，在 𝒱' 内对角化。一阶修正由非对角元 ⟨D_new|H|ψ_𝒱⟩ = ⟨D_new|r⟩ 驱动（⟨D_new|ψ_𝒱⟩ = 0）。能量下降量 ∝ |⟨D_new|r⟩|² / (⟨D_new|H|D_new⟩ - E_𝒱)。∎

**推论 10.88.3.04（新波包中心的选择判据）**。由命题 10.88.3.03，单方向添加的能量修正 ∝ |⟨D_new|r⟩|² / (⟨D_new|H|D_new⟩ - E_𝒱)，故**能量最优**的单行列式中心应最大化 |⟨D_new|r⟩|² / |⟨D_new|H|D_new⟩ - E_𝒱|——即分母加权判据（与 CIPSI 的 PT2 选择判据 |H_DI|²/(H_DD − E) 同构），而非单纯 |⟨D_new|r⟩|。当前实现（§3.1 step d）用简化判据 argmax_{D∉𝒱}|⟨D|r⟩|（忽略分母，§6 的实测数据均由此判据产生）；两判据的**实测对比见 §9.3 #6**（三个系统上最终能量一致、波包数相同，仅中心序列可能分叉——判据只改路径不改终点）。而 W(D_new) = supp(H|D_new⟩) 自动包含 D_new 的 Bruhat 2-邻域，因此添加一个波包等价于添加 ~行度 个新方向（而非 1 个），加速收敛。

### §3.4　变分空间的 Bruhat 连通性

**命题 10.88.3.05（变分空间的 Bruhat 连通性，定理）**。WCI 的变分空间 𝒱 始终是 Bruhat 图上的连通子图。

**证明**。初始 𝒱 = W(D_0) 是 Bruhat 2-球，显然连通。设第 k 轮的 𝒱_k 连通。新波包中心 D_new 满足 ⟨D_new|r⟩ ≠ 0（残差最大），而 r = H|ψ⟩ - E|ψ⟩，|ψ⟩ ∈ 𝒱_k。因此 ⟨D_new|H|D⟩ ≠ 0 对某个 D ∈ 𝒱_k 成立（否则 ⟨D_new|H|ψ⟩ = 0，残差为零）。由命题 10.88.2.03，d_B(D_new, D) ≤ 2，即 D_new 与 𝒱_k 中某个态的 Bruhat 距离 ≤ 2。而 W(D_new) 包含 D_new 及其 Bruhat 2-邻域，故 W(D_new) 与 𝒱_k 有交集（至少包含 D）。因此 𝒱_{k+1} = 𝒱_k ∪ W(D_new) 连通。∎

**意义**：Bruhat 连通性保证变分空间不会碎片化——每个新波包都与已有空间有 H 连接，残差驱动的添加不会引入孤立态。这是 top-k 截断（可能丢弃桥梁态导致碎片化）所不具备的几何性质。

## §4　变分收敛性证明

### §4.1　单调收敛

**定理 10.88.4.01（WCI 单调收敛，定理）**。WCI 算法的能量序列 {E_k} 单调不增：E_{k+1} ≤ E_k，且 E_k ≥ E_0（精确基态能量）。因此 {E_k} 收敛到某个 E_* ≥ E_0。

**证明**。每轮添加新波包后变分空间严格增大（𝒱_k ⊂ 𝒱_{k+1}，因为新波包中心 D_new ∉ 𝒱_k，且 D_new ∈ W(D_new) ⊆ 𝒱_{k+1}）。由命题 10.88.3.02（Rayleigh-Ritz 单调性），E_{k+1} ≤ E_k。又由变分下界 E_k ≥ E_0。单调有界序列必收敛。∎

### §4.2　精确收敛条件

**定理 10.88.4.02（残差为零 ⇔ 精确基态，定理）**。若 ||r_out|| = 0（空间外残差为零），则 |ψ⟩ 是 H 的精确本征态，E 是精确本征值。若 |ψ⟩ 是基态（变分空间包含基态方向），则 E = E_0。

**证明**。r = H|ψ⟩ - E|ψ⟩。||r_out|| = 0 意味着 P_{⊥} r = 0，即 r ∈ 𝒱。但 r_in = P_𝒱 r = P_𝒱 (H|ψ⟩ - E|ψ⟩) = H_𝒱|ψ⟩ - E|ψ⟩ = 0（因为 |ψ⟩ 是 H_𝒱 的本征向量，本征值 E）。因此 r = r_in + r_out = 0，即 H|ψ⟩ = E|ψ⟩。|ψ⟩ 是精确本征态。若 |ψ⟩ 是变分空间内的最低本征态且变分空间包含精确基态方向，则 E = E_0。∎

**推论 10.88.4.03（有限步收敛）**。若变分空间 𝒱 包含精确基态 |ψ_0⟩ 的支撑集（即 |ψ_0⟩ = Σ_{D∈𝒱} c_D |D⟩），则 WCI 在有限步内收敛到 E_0（因为 Rayleigh-Ritz 在包含基态的空间内精确恢复基态）。

### §4.3　与 top-k 幂迭代的收敛性对比

| 性质 | top-k 幂迭代 | WCI |
|---|---|---|
| 收敛目标 | 绝对值最大本征值（不一定基态） | 变分空间内最低本征值（恒为基态近似） |
| 单调性 | 幅值单调增，能量不一定单调 | 能量单调不增（变分原理保证） |
| 收敛保证 | 需 shift 且基态为绝对值最大 | 无需 shift，恒收敛到变分基态 |
| 空间结构 | 无结构（幅值截断） | Bruhat 连通（波包并集） |
| k 选择 | 人工选择，经验标度 | 残差驱动，自适应 |

## §5　实现细节

### §5.1　核心数据结构

**Wavepacket 类**（`geoqc_wci.py`）：

```
Wavepacket(center, apply_fn, hd_fn, db, az_of, bz_of, rt_a, rt_b)
├── center: int          # 中心行列式的 rank table 索引
├── support: np.ndarray   # 支撑集 = supp(H|center⟩)，已排序、去重
└── size: int             # 支撑集大小
```

支撑集通过 `apply_H([1], [center])` 生成——H·中心自然返回所有 1-2 激发目标（含两体对角），即 Bruhat 2-球。

### §5.2　完整 H|ψ⟩ 的构造

**命题 10.88.5.01（完整 H|ψ⟩ 的分解，实现命题）**。完整 H|ψ⟩ = apply（激发项 + 两体对角）+ hd_fn（单电子对角）。

- `apply(azs, bzs, vals)`：返回 (t_az, t_bz, t_v)，包含所有 1-2 激发的非对角项 + 两体对角项（row == col 的两体贡献）；
- `hd_fn(idxs)`：返回单电子对角 ⟨D|h_1body|D⟩（two_body=False）；
- 合并：`np.unique` + `np.add.at` 将 apply 输出和 hd_fn 输出按目标索引合并。

**注意（10.87 §6.06 的对角双重计数 bug）**：apply 含两体对角，hd_fn 必须用 two_body=False（仅单电子对角），否则对角元被双重计数。10.87 §6.06 记录了此 bug 及修复。

### §5.3　HF 种子

**命题 10.88.5.02（HF 种子的构造，实现命题）**。初始波包中心取 HF 行列式：从单电子能级 e_a[k] = o_s[2k,2k]（alpha）、e_b[k] = o_s[2k+1,2k+1]（beta）中选最低 n_a/n_b 个轨道占据，计算 bitstring → rank table 查表。

HF 态是单参考系统的最优初始中心（10.87 §6.03 证实单参考基态 = 1 个 HF 波包主导）。对于多参考系统，HF 种子仍可通过残差驱动添加其他重要组态的波包。

### §5.4　大 dim 的按需对角

**命题 10.88.5.03（大 dim 的对角策略，实现命题）**。同 `geoqc_kscan.py`：阈值 DIAG_FULL_LIMIT = 2,000,000。小 dim 建全数组并包装为 callable `hd_fn(idxs) = _hd_arr[idxs]`；大 dim 用 `sector_diagonal_at` 按需计算（O(1) 查单电子对角，不建全数组）。

## §7　性能优化：三层向量化与增量构造

### §7.1　原始实现的瓶颈分析

LiH/6-31G（dim=3025，28 轮迭代）原始实现总时间 **175.2s**，其中：

- H 矩阵构造（第 28 轮）：**9.8s**（1511 次逐态 apply + 字典查找填充）
- 残差计算（第 28 轮）：2.1s（一次全空间 apply_H）
- 对角化：含在 H 时间内（complex128 eigh ~6.7s）

### §7.2　优化一：np.searchsorted 代替字典查找

**问题**：原始 `build_H_matrix` 对每个目标行列式用 `idx_to_pos.get(int(ui))` 字典查找定位其在变分空间中的位置。Python 字典查找 + Python 循环是瓶颈。

**方案**：变分空间 `unique_idx` 已排序，用 `np.searchsorted(unique_idx, u)` 向量化查找所有目标的位置，再用布尔掩码过滤有效目标。

```python
# 原始（Python 循环 + 字典）
for ui, wi in zip(u, w):
    i = idx_to_pos.get(int(ui))
    if i is not None:
        H_mat[i, j] = wi

# 优化（numpy 向量化）
pos = np.searchsorted(unique_idx, u)
valid = pos < n
if valid.any():
    valid[valid] &= unique_idx[pos[valid]] == u[valid]
H_mat[pos[valid], j] = w[valid]
```

**效果**：H 矩阵填充加速 ~17%，LiH/6-31G 总时间 175.2s → 161.1s。

### §7.3　优化二：增量 H 矩阵构造

**问题**：每轮变分空间仅新增 ~150-200 个态（一个波包的支撑集），但原始实现对全部 n_var 个态重新做 apply 构造 H 矩阵。第 28 轮 n_var=1511，但仅新增 2 个态——1509 个旧态的 H 矩阵元完全可以复用。

**方案**：`_build_H_incremental(unique_idx, unique_idx_prev, H_mat_prev, ...)`：

1. 用 `np.isin` 找出新增态（new_mask = ~np.isin(unique_idx, unique_idx_prev)）；
2. 创建新矩阵 H_mat，旧块 `H_mat[old_pos, old_pos] = H_mat_prev`（花式索引复制）；
3. 仅对新增态做 apply_H，填充新列 `H_mat[:, new_pos]`；
4. 由 Hermiticity 填充新行：`H_mat[new_pos, :] = H_mat[:, new_pos].conj().T`。

**关键 bug 修复**：最初实现用 `(H_mat + H_mat.conj().T) / 2` 对称化，但新行 `H_mat[new_pos, old_pos]` 未填充（为 0），对称化会把新列值除以 2（`(正确值 + 0)/2`）。调试发现第 2 轮 H 矩阵 max diff = 7.7e-2（恰好 full=-0.1536, incr=-0.0768，一半）。修复：用新列共轭转置显式填充新行，不再做平均对称化。修复后 max diff = 1.8e-15（机器精度）。

**效果**：第 28 轮 H 矩阵构造本身从 1.9s（完整构造）→ 0.025s（增量构造），**77 倍加速**。但总时间仍受对角化瓶颈限制（complex128 eigh ~6.7s）。

### §7.4　优化三：float64 代替 complex128

**问题**：分子积分在实基组（STO-3G、6-31G 等）下全部为实数，H 矩阵是实对称矩阵。但原始实现用 complex128 存储（为通用性），`np.linalg.eigh` 对 Hermitian 复矩阵比对实对称矩阵慢约 17 倍。

**方案**：
1. `apply_H` 中取 `np.asarray(t_v).real` 和 `np.asarray(hd_fn(idx) * vals).real`，用 float64 存储；
2. `build_H_matrix` 和 `_build_H_incremental` 中 H 矩阵用 `dtype=float`；
3. `np.linalg.eigh` 自动对实对称矩阵使用更快的算法。

**效果**：第 28 轮对角化从 ~6.7s（complex128）→ ~0.3s（float64），**17 倍加速**。H 矩阵构造（含对角化）从 6.8s → 0.4s。

| 层 | 优化 | 总时间 | 累计加速 | 关键技术 |
|---:|---|---:|---:|---|
| 0 | 原始（complex+完整H+字典+Python单激发） | 175.2s | 1.0× | — |

| 2 | 增量 H 矩阵构造 | 146.9s | 1.19× | 旧块复用 + Hermiticity 填充 |
| 3 | float64 代替 complex128 | 44.1s | 3.97× | 实对称 eigh 快 17× |
| 4 | 增量残差（H_cols 缓存） | 9.9s | 17.7× | 逐列缓存 H\|D⟩，线性组合求残差 |
| 5 | 向量化 apply 单激发枚举 | 7.6s | 23.1× | 预计算 SE term array + numpy 向量化筛选 |
| 6 | Davidson 对角化替换稠密 eigh | 3.0s | 58.4× | scipy eigsh + LinearOperator，O(V²) 内存 |
| 7 | 批量 apply + H_build 完全向量化 | 2.80s | 62.6× | sparse_action_sz_vec 批量 + 向量化填充 |
| 8 | Davidson 调参（tol=1e-8, ncv=20） | **2.33s** | **75.1×** | 化学精度足够的容差 + 更大 Krylov 子空间 |

**总时间：175.2s → 2.33s（75.1 倍加速）**
**能量精度：LiH/6-31G 误差 8.2e-05 Ha（0.08 mHa，化学精度内），三系统验证全部通过。**

### §7.6　优化四：增量残差（H_cols 缓存）

**问题**：每轮残差计算 `compute_residual` 对全部 n_var 个态做一次全空间 `apply_H`，第 28 轮 n_var=1511，耗时 ~1.5s，占总时间 75%。但每轮仅新增 ~150-200 个态，旧态的 H|D⟩ 列完全可以复用。

**方案**：`compute_residual_incremental(coeffs, unique_idx, E, H_cols)`：

1. 在 `build_H_incremental` 中，对每个新增态缓存 `H_cols[D] = (target_idx, H_val)`（即 H|D⟩ 列的稀疏表示）；
2. 残差计算时，对变分空间中每个态 D，取 `H_cols[D]`，乘以系数 c_D，线性组合得到 H|ψ⟩ = Σ_D c_D · H|D⟩；
3. 用 `np.unique` + `np.add.at` 合并所有列的贡献，得到 H|ψ⟩ 的稀疏表示；
4. 残差 r = H|ψ⟩ - E|ψ⟩，在变分空间内为 0（变分原理），空间外即为残差。

**关键洞察**：H_cols 缓存的是 H|D⟩ 列（每个源态单独的列），而不是 H|ψ⟩。因为系数 c_D 每轮变化，H|ψ⟩ 不能直接缓存，但 H|D⟩ 列是固定的，可以缓存后线性组合。

**效果**：残差计算从 ~1.5s/轮 → ~0.014s/轮，**107 倍加速**。总时间 44.1s → 9.9s。

### §7.7　优化五：向量化 apply 单激发枚举

**问题**：`exterior.py` 中 `sparse_action_sz` 的 apply 闭包对单激发枚举使用 Python 循环（遍历每个占据轨道 i 和虚轨道 a），每个态 ~n_a×n_v 次循环。LiH/6-31G 每轮新增 ~150 态，每态 ~2×9=18 次单激发循环，Python 循环开销显著。

**方案**：预计算单激发 term array（SE_A/SE_B），包含所有可能的 (i, a) 组合的系数、符号、位操作参数。apply 时用 numpy 向量化筛选（布尔掩码）代替 Python 循环：

```python
# 原始（Python 循环）
for i in occ_alpha:
    for a in virt_alpha:
        if t_s[2*a, 2*a, 2*i, 2*i] > tol:
            az2 = az ^ (1<<i) ^ (1<<a)
            ...

# 优化（numpy 向量化）
mask = (coefA > tol) & occA[:, SE_A.occ] & (~virtA[:, SE_A.virt])
az2 = azs[:, None] ^ rm_occ[None, :] ^ rm_virt[None, :]
...
```

**效果**：apply 单激发部分加速 ~5×。总时间 9.9s → 7.6s。

### §7.8　优化六：Davidson 对角化替换稠密 eigh

**问题**：前五层优化后，对角化成为新的最大瓶颈（占 75%）。`np.linalg.eigh` 对 V×V 稠密矩阵做 O(V³) 分解，LiH/6-31G V=1511 时 ~209ms/轮，且 V>10⁵ 时 O(V²) 内存不可行。

**方案**：`_eigh_ground(H_mat, k=3, tol=1e-8)`：

1. V > 300 时用 `scipy.sparse.linalg.eigsh`（implicitly restarted Lanczos），只请求 k=3 个最小本征对；
2. 用 `LinearOperator` 封装稠密 H 的 matvec（`H_mat @ x`），避免转换为稀疏矩阵；
3. V ≤ 300 时回退稠密 eigh（Lanczos overhead 占优）。

**可行性突破**：Davidson/Lanczos 仅需 O(V×k) 内存（k=3），而稠密 eigh 需要 O(V²)。V>10⁵ 时稠密 eigh 内存不可行，Davidson 是唯一选择。

**效果**：对角化从 209ms/轮 → ~50ms/轮，**4.2 倍加速**。总时间 7.6s → 3.0s。

### §7.9　优化七：批量 apply + H_build 完全向量化

**问题**：Davidson 优化后，H_build 成为第二大瓶颈（占 19%）。`build_H_incremental` 对每个新增态逐态循环调用 `apply_H`（Python for 循环），每个态内部调用标量版 `sparse_action_sz`。虽然单激发已向量化，但双激发仍是 Python 循环，且逐态调用有 Python overhead。

**方案**：

1. **切换到 `sparse_action_sz_vec`**：exterior.py 中已有的完全向量化版本（单激发+双激发都向量化，支持批量输入 S 个源态），文档验证比标量版快 ~5×；
2. **修改 `sparse_action_sz_vec` 返回源态索引**：apply 闭包返回第四个值 `src_idx`（每个激发项属于哪个源态），用于批量处理后按源态拆分到 H_cols；
3. **重写 `build_H_incremental` 为完全向量化**：
   - 所有新增态批量调用一次 apply_fn（代替逐态循环）；
   - H 矩阵填充用单次向量化 `np.searchsorted` + `np.add.at`（代替逐态 searchsorted）；
   - H_cols 缓存用 `np.argsort` 分组（代替逐态存储）。

**关键 bug 修复**：批量填充时，同一个 (源,目标) 对可能有多个激发项（如 alpha+beta 单激发都指向同一目标），直接赋值 `H_mat[row, col] = val` 会覆盖而非相加。必须用 `np.add.at` 累加重复项。修复前能量错误（差 6.26 Ha），修复后能量正确（误差 0.08 mHa）。

**效果**：apply_fn alone 加速 4.9×（0.66→0.13 ms/态），但 H_build 总加速受其他开销（searchsorted、argsort、np.add.at）限制。总时间 3.0s → 2.80s。

### §7.10　优化八：Davidson 调参（tol=1e-8, ncv=20）

**问题**：cProfile 显示 Davidson 对角化仍占 55.6%，其中 matvec (H@x) 占 46.8%。scipy eigsh 默认 `tol=0`（机器精度）和 `ncv=min(2k+1, V)=7`，导致需要 ~153 次 matvec/轮才能收敛。

**方案**：

1. **降低 tol 到 1e-8**：WCI 能量误差由变分空间截断主导（~1e-4 Ha），对角化精度 1e-8 远小于变分误差，不影响最终结果；
2. **增加 ncv 到 20**：更大的 Krylov 子空间减少重启次数，从而减少 matvec 总次数。

**效果**：Davidson 对角化从 ~1.93s → ~1.2s，**1.6 倍加速**。总时间 2.80s → 2.33s。

### §7.11　当前瓶颈与下一步

八层优化后，cProfile（LiH/6-31G, V=1509, 29 波包）显示：

| 阶段 | 时间 | 占比 |
|---|---:|---:|
| Davidson 对角化 | ~1.2s | ~52% |
| └ matvec (H@x) | ~1.0s | ~43% |
| H_build（批量 apply + 向量化填充） | ~0.5s | ~21% |
| 残差计算（增量 + np.unique） | ~0.4s | ~17% |
| 其他（vspace/select/overhead） | ~0.2s | ~10% |

**Davidson matvec 是当前最大瓶颈**（43%）。H 是稠密 V×V 矩阵，每次 matvec 是 O(V²)，np.dot 已用 BLAS 优化。进一步优化方向：

1. **真正的 Davidson 方法（带对角预条件）**：scipy eigsh 用的是 Lanczos 方法（无预条件），实现带预条件的 Davidson 可显著减少 matvec 次数；
2. **H 矩阵稀疏化**：WCI 变分空间中 H 矩阵的非零元比例可能远低于 100%，用稀疏矩阵存储和 matvec 可减少 O(V²) 操作；
3. **残差计算 np.unique 优化**：占 13%，可用 scipy.sparse 或更高效的合并方法代替；
4. **NO 基选项**：10.87 §6.05 验证 NO 基使 eff-dim 降 289 倍，可显著减少波包数和变分空间大小，从根本上减少所有阶段的时间。

#### §7.12.2　GPU 双激发 kernel 设计

在 AMD Radeon RX 570（8GB GDDR5, 32 CU, OpenCL 1.2）上实现双激发并行化：

**计算模式**：每个 work-item 处理一个 (source, term) 对，执行：
1. 检查 r,s 占据（位操作）
2. 湮灭 s → 湮灭 r（各一次 `_spin_sign`）
3. 检查 q 空 → 产生 q（`_spin_sign`）
4. 检查 p 空 → 产生 p（`_spin_sign`）
5. 原子计数器 `atomic_inc` 收集稀疏输出

**符号计算**：用 OpenCL 内置 `popcount(long)`，与 exterior.py 的 `_spin_sign` 完全等价：
- alpha_k: `popcount(az & ((1<<k)-1)) + popcount(bz & ((1<<k)-1))`
- beta_k: `popcount(az & ((1<<(k+1))-1)) + popcount(bz & ((1<<k)-1))`

**关键正确性细节**：
- **湮灭算符**符号用**湮灭前**位串计算
- **产生算符**符号用**产生后**位串计算（与 exterior.py 一致，最初误用产生前导致单扇区双激发符号错误）

**分块处理**：chunk_size=64 源态/块，避免 S×T 全网格（S=5000, T=126484 → 6.3 亿 work-item）超出全局工作项限制。每块独立创建源态 buffer，kernel 内索引从 0 开始。

### §7.13　优化十：GPU 加速残差计算（argsort 瓶颈的突破）

**[程序标注]** `geoqc/gpu.py::GPUArgsort`（int32 稳定 radix sort 携带 index）+ `geoqc/gpu.py::GPUArgsort64`（int64 版本，用于 dim>2³¹ 的大系统）+ `geoqc/wci.py::compute_residual_incremental(gpu_argsort=...)`（自动选择 CPU/GPU argsort）。

#### §7.13.1　残差计算的瓶颈分析

§7.12 的 GPU 双激发加速把 H_build 从 33s 降到 11s，但端到端加速仅 2.21x，因为残差计算成为新的未加速瓶颈：

| 阶段 | CPU (2波包) | GPU doubles | 占比（GPU 端） |
|---|---:|---:|---:|
| H_build | 32.7s | 10.8s | 62% |
| **残差计算** | **5.7s** | **5.7s（未加速）** | **33%** |
| Davidson + 其他 | <1s | <1s | 5% |

残差计算的核心是列线性组合的合并：`H|ψ⟩ = Σ_D c_D · H|D⟩`，每个 H|D⟩ 是稀疏的 (target, value) 列表。合并需要对所有 target 排序后分组求和。

**残差时间分解**（H₂O/cc-pVDZ 第1轮，1340 万元素）：

| 操作 | 时间 | 占比 |
|---|---:|---:|
| `np.argsort`（排序） | 1.0s | **59%** |
| loop + concatenate（列收集） | 0.3s | 18% |
| gather（重排 value） | 0.2s | 12% |
| diff + reduceat（分组求和） | 0.1s | 6% |
| searchsorted + add.at | 0.1s | 5% |

**argsort 是绝对瓶颈**，占残差时间的 59%。

#### §7.13.2　CPU 优化：argsort + reduceat 代替 np.unique

原始实现用 `np.unique(return_inverse=True) + np.add.at`，对 1340 万元素需 2.5s。优化为 `argsort + reduceat`：

**原理**：排序后相同 target 连续，用 `diff` 找边界，`reduceat` 分段求和。

**关键细节**：
- 自动选择 int32（max<2³¹）或 int64，int32 比 int64 快 23%
- 必须用默认 quicksort，`kind='stable'` 慢 2.7 倍（reduceat 不需要稳定性，相同 target 求和顺序无关）

**性能**：1340 万元素从 2.5s 降到 1.8s，加速 1.4x。

#### §7.13.3　GPU argsort：稳定 radix sort 携带 index

CPU argsort 仍是瓶颈。在 GPU 上实现稳定 radix sort，关键挑战是**必须返回 argsort 索引**（用于重排 value），而非仅排序后的值。

**算法设计**（32 轮 radix sort，每轮 3 个 kernel）：

1. **bit+hist kernel**：计算每个元素的当前 bit，`atomic_add` 统计 1-bit 总数
2. **GenericScanKernel 前缀和**：对 bit 数组做 inclusive prefix sum（`pyopencl.scan.GenericScanKernel`）
3. **scatter kernel**：根据前缀和计算输出位置，**同时交换 key 和 index**
   - bit=0: `pos = i - prefix1[i]`
   - bit=1: `pos = h0 + prefix1[i] - 1`

**符号位处理**：`key = (unsigned int)data[i] ^ 0x80000000u`，使负数排在正数前。

**为什么必须稳定**：radix sort 从低位到高位依次排序，每轮必须保持低 k 位的已有顺序。非稳定排序（如 `atomic_inc` 分配位置）会打乱低位顺序，导致最终结果不完全有序，相同 target 不连续，reduceat 分组错误。

**int64 支持**：对于 dim>2³¹ 的大系统（如 NH₃/cc-pVDZ, dim=1.41×10¹⁰），target 索引是 int64。`GPUArgsort64` 用 64 轮 radix sort，kernel 用 `long` 类型，index 仍用 int32（残差元素数 <2³¹）。

| 结构化数组同时排序 (target,value) | 14.5s（慢6倍） | numpy 结构化数组排序远慢于 int32 argsort |
| stable argsort（kind='stable'） | 2.9s（慢2.7倍） | 归并排序开销大，reduceat 不需要稳定性 |

### §7.14　优化十一：占据感知双激发（dim=10¹⁵ 目标的关键突破）

#### §7.14.1　问题：大系统双激发的计算量爆炸

§7.12 的 GPU 双激发 kernel 遍历所有可能的双激发项 T = C(n_orb,2)² × 4，无论 r,s 是否被占据。对于大系统，T 随 n_orb⁴ 增长：

| n_orb | dim | T_all（双激发项数） | 每态 H|D⟩ 时间估算 |
|---:|---:|---:|---:|
| 24 | 1.8×10⁹ | 304,704 | ~10 ms |
| 29 | 1.4×10¹⁰ | 707,281 | ~16 ms |
| 85 | 1.1×10¹⁵ | **50,979,600** | **~800 ms/态** |

n_orb=85（dim≈10¹⁵）时，每态仅双激发就需要 ~800 ms。WCI 每轮约 2000 态、10 轮，总计 20000 态 × 800 ms = **16000 秒 ≈ 4.4 小时**（仅双激发，不含 singles/残差/对角化）。加上其他开销后远超 24 小时目标。

根本原因：GPU kernel 遍历了大量 r,s 未被占据的"零激发"——这些项的矩阵元恒为零，但仍消耗了 99.5% 的计算量。

#### §7.14.2　理论发现：H|D⟩ 的非零元数与 dim 无关

对于 1-2 体哈密顿量，双激发算符 a_p† a_q† a_s a_r 仅当 r,s 被源态 |D⟩ 占据时才非零。给定 n_occ=5（10 电子体系），非零双激发数为：

```
N_doubles = C(n_occ,2)·C(n_vir,2)   [aa]
          + C(n_occ,2)·C(n_vir,2)   [bb]
          + n_occ²·n_vir²            [ab]
```

其中 n_vir = n_orb - n_occ。关键性质：**N_doubles 仅随 n_vir² 增长（O(n_orb²)），而非 T_all 的 O(n_orb⁴)**。

| n_orb | n_vir | N_doubles（非零） | T_all（全部） | 非零比例 | 计算量减少 |
|---:|---:|---:|---:|---:|---:|
| 24 | 19 | 20,410 | 304,704 | 6.7% | 14.9× |
| 29 | 24 | 33,120 | 707,281 | 4.7% | 21.4× |
| 85 | 80 | **223,200** | **50,979,600** | **0.44%** | **228.4×** |

n_orb=85 时，只需遍历 223,200 个非零激发，而非 5098 万个——计算量减少 **228 倍**。这是达成 24 小时目标的理论关键。

这一发现的几何本质：H|D⟩ 的支撑集是 Bruhat 球 B(D,2)，其大小由 D 的占据结构决定，与整个行列式空间的维度 dim 无关。dim 增大只意味着空轨道增多，但每个源态的占据轨道数固定（n_occ=5），因此非零激发数有上界。

#### §7.14.3　占据感知双激发的算法设计

核心思想：对每个源态 |D⟩，先收集其占据轨道（5 alpha + 5 beta）和空轨道，然后只枚举 r,s ∈ 占据、p,q ∈ 空的双激发。

三种自旋类型的枚举：

| 类型 | 湮灭轨道 | 产生轨道 | 数量 | 过滤条件 |
|---|---|---|---|---|
| aa | r,s ∈ occ_a (r<s) | p,q ∈ vir_a (p<q) | C(5,2)·C(n_vir,2) | combinations |
| bb | r,s ∈ occ_b (r<s) | p,q ∈ vir_b (p<q) | C(5,2)·C(n_vir,2) | combinations |
| ab | r ∈ occ_a, s ∈ occ_b | p ∈ vir_a, q ∈ vir_b | 25·n_vir² | 无需过滤（p<q, r<s 恒成立） |

系数公式（自旋轨道积分 t_s，含 spin_orbital_integrals 的 1/2 因子和 adbc→abcd 重排）：

```
aa/bb: c2 = 2·(t_s[2p,2q,2r,2s] - t_s[2p,2q,2s,2r])
ab:    c2 = 2·(t_s[2p,2q+1,2r,2s+1] - t_s[2p,2q+1,2s+1,2r])
       = 2·(0 - t_s[2p,2q+1,2s+1,2r])   [0,1,0,1 自旋模式不在 aaaa/bbbb/abba/baab 中]
```

符号计算（湮灭 s → 湮灭 r → 产生 q → 产生 p，每步用 popcount 计算外代数符号）：

```
湮灭 k（alpha）: (-1)^{popcount(az & ((1<<k)-1)) + popcount(bz & ((1<<k)-1))}
湮灭 k（beta）:  (-1)^{popcount(az & ((1<<(k+1))-1)) + popcount(bz & ((1<<k)-1))}
产生 k:          与湮灭同公式（产生算符符号用产生前位串）
```

#### §7.14.5　GPU kernel 设计

每个 work-group 处理一个源态，256 个 work-item 并行枚举该态的所有非零双激发：

1. **收集阶段**（tid=0）：遍历位串，将占据轨道存入 `__local occ_a[5]/occ_b[5]`，空轨道存入 `__local vir_a[80]/vir_b[80]`，barrier 同步
2. **枚举阶段**（所有 tid）：将总激发数（aa+bb+ab）展平为线性索引，每个 work-item 处理 `idx = tid, tid+256, tid+512, ...`
3. **解码阶段**：将线性索引解码为 (type, r, s, p, q)。aa/bb 用对索引解码公式 `i = n-2-floor(sqrt(-8k+4n(n-1)-7)/2-0.5)`；ab 直接用除法解码
4. **计算阶段**：查空间积分、计算系数、4 步 popcount 符号、目标位串
5. **输出阶段**：`atomic_inc(counter)` 获取位置，写入 (az, bz, val, src)

关键优化：**输出 buffer 按需读取**。先读 counter 获实际输出数 n_out，再分配精确大小的 hostbuf 读取——而非预分配最大 buffer 后全量读取。这一项将 NH₃/cc-pVDZ 上的性能从 3.16× 提升到 **26.96×**（避免了每次读取 800 万元素 × 28 字节 = 224 MB 的无效数据传输）。

#### §7.14.6　空间轨道积分（大系统显存适配）

n_orb=85 时，自旋轨道积分 t_s 的大小为 (2×85)⁴ × 8 字节 = **6.7 GB**，超过 RX 570 的 8 GB 显存（扣除 kernel/输出 buffer 后实际可用约 6 GB）。

解决方案：使用空间轨道积分 t_spatial（n_orb⁴ × 8 字节 = **418 MB**），在 kernel 中按自旋类型转换为有效系数。

转换关系（来自 `integrals.spin_orbital_integrals`：v = 0.5·einsum("adbc->abcd", t_chem)，自旋布局 aaaa/bbbb/abba/baab）：

| 类型 | 空间轨道积分公式 | 推导 |
|---|---|---|
| aa/bb | `c2 = t_chem[p,s,q,r] - t_chem[p,r,q,s]` | 2·(0.5·t_chem[p,s,q,r] - 0.5·t_chem[p,r,q,s]) |
| ab | `c2 = -t_chem[p,r,q,s]` | t_s[2p,2q+1,2r,2s+1]=0（自旋模式 0,1,0,1 不匹配），t_s[2p,2q+1,2s+1,2r]=0.5·t_chem[p,r,q,s]（abba），c2=2·(0-0.5·t_chem)=-t_chem |

**注意**：这一转换极易出错。最初版本误用 `c2 = 2·(t_chem[p,q,r,s] - t_chem[p,q,s,r])`（物理学家记号直接套用），导致 H₂O/cc-pVDZ 上 57,545 个输出全部不匹配（数值差约 10 倍）。必须严格按照 `spin_orbital_integrals` 的 1/2 因子、adbc→abcd 重排、abba/baab 自旋布局逐步推导。该函数源码中有详细警告："THIS IS THE ONLY CORRECT ENTRY POINT — DO NOT HAND-ROLL"。

#### §7.14.10　调试记录：64 位位串符号计算的溢出 bug

**问题现象。** H₂O/cc-pVTZ（n_orb=58, dim=2.1×10¹³）WCI 端到端测试能量异常低：E=-81.54 Ha，远低于 CCSD(T)=-76.35 Ha。WP1 E=-80.14, WP2 E=-81.54，能量持续下降且违反变分原理（应 ≥ FCI）。

**逐层排查。**

1. **RankTable 验证**：HF 态 idx=0，az_of[0]=0x1f，5 个随机态的 rank→bitstring→rank 往返全部正确，popcount 均为 n_occ=5。排除排名计算错误。
2. **HF 对角能验证**：one-body=-113.888, two-body=37.831, total=-76.057=RHF，误差 1.4e-14。排除积分和 HF 态计算错误。
3. **H 矩阵厄米性检查**：200 态变分空间，max asymmetric element = 0.00e+00。排除非厄米导致虚假低本征值。
4. **最低对角元定位**：变分空间中最低对角元 E=-80.12 Ha（比 HF 低 4 Ha），对应态为 alpha 单激发 3→32（alpha occ=[0,1,2,4,32]）。
5. **CPU vs GPU 自身对角能对比**：该态 CPU 二体对角能=35.572 Ha，GPU=27.466 Ha，**差异 8.106 Ha**。

**根本原因。** GPU kernel 符号计算部分存在两处 64 位位串处理错误：

```c
// 错误代码（修复前）
int mask_s = (1 << ks) - 1;                          // ks>=32 时 int 溢出
int cnt_s = popcount((unsigned int)(saz & mask_s))  // 截断高 32 位
         + popcount((unsigned int)(sbz & mask_s));
```

- **`1 << ks` 溢出**：当轨道索引 ks≥32 时，32 位 int 的左移是未定义行为（通常结果为 0 或回绕），导致 mask_s 计算错误。
- **`(unsigned int)` 截断**：saz/sbz 是 64 位 long，强制转换为 unsigned int 会丢弃高 32 位。当位串的第 32 位以上有电子占据时（如激发到轨道 32），popcount 结果错误，进而符号计算错误。

**为什么小系统没暴露。** H₂O/cc-pVDZ（n_orb=24）所有轨道索引 <32，`1 << ks` 不溢出，`(unsigned int)` 也不截断，因此 CPU vs GPU 完全匹配。H₂O/cc-pVTZ（n_orb=58）有大量激发到轨道 ≥32 的态，bug 才暴露。

**修复方案。**

```c
// 修复后
long mask_s = (1L << ks) - 1;                          // 64 位长整型
int cnt_s = popcount((unsigned long)(saz & mask_s))   // 64 位 popcount
         + popcount((unsigned long)(sbz & mask_s));
```

共 8 处修改：4 处 mask 计算（湮灭 s/r、产生 q/p），4 处 popcount 截断。

**修复后验证。** H₂O/cc-pVTZ 上 5 个态（含激发到轨道 32/40/35 的高能级激发）CPU vs GPU 自身对角能：

| 态 | CPU total (Ha) | GPU total (Ha) | 误差 |
|---|---:|---:|---:|
| HF | -76.056783 | -76.056783 | 0.00e+00 |
| single_a 3→32 | -72.014077 | -72.014077 | 0.00e+00 |
| single_a 0→40 | -51.714661 | -51.714661 | 7.11e-15 |
| single_b 2→35 | -71.784017 | -71.784017 | 1.42e-14 |
| double_aa (0→32,1→40) | -46.599351 | -46.599351 | 7.11e-15 |

修复前 single_a 3→32 差异 8.11 Ha，修复后 0.00e+00。

**教训。** 64 位位串在 GPU OpenCL kernel 中处理时，所有位运算必须显式使用 `1L`（long 字面量）和 `(unsigned long)` 类型转换，不能依赖隐式类型提升。这是跨 n_orb>32 系统的通用陷阱。

### §7.15　优化十二：内存崩溃定位与分块处理（dim=10¹³→10¹⁵ 的工程通行证）

**问题背景。** 在推进 dim=10¹⁵ 目标过程中，多次遭遇电脑因内存不足重启（16GB 系统）。5000 态 × 2 波包在 H₂O/cc-pVTZ（dim≈2.1×10¹³）上反复 OOM，WP2 从未完整跑完。

**逐层定位（子进程隔离 + 超时保护的安全测试方法论）。**

1. **apply_fn 大批量阈值测试**：逐步增加态数（100→6000），每个测试在独立子进程中运行，超时 300s 自动 kill。

| 态数 | 时间 | 峰值内存 | 结果 |
|---:|---:|---:|---|
| 100 | 0.42s | 4.9GB | 通过 |
| 1000 | 4.05s | 6.6GB | 通过 |
| 2000 | 14.14s | 7.7GB | 通过 |
| 5000 | 52.52s | 9.3GB | 通过 |
| 6000 | TIMEOUT | >16GB | swap 超时 |

**根本原因**：不是 GPU 崩溃，是 `build_H_matrix` 一次性存储所有 apply_fn 输出。5000 态 × ~10 万耦合/态 = 5 亿输出项，纯数据就 8GB+，加上 H 矩阵和临时数组超过 16GB。

2. **build_H_matrix 内存优化（第一版）**：原实现分块调用 apply_fn，但所有块的输出存储在 `all_t_idx/all_t_v/all_src` 列表中，最后 `concatenate` 成大数组再一次性填充 H 矩阵。优化后：每块调用 apply_fn 后直接 `searchsorted + np.add.at` 填充 H_mat，立即 `del` 临时数组。峰值内存从 O(总输出项) 降到 O(H 矩阵本身)。

3. **H_cols 内存优化（两版迭代）**：
   - **第一版（失败）**：H_cols 只存储空间内目标态（减少 90%），但空间外残差需要重新调用 apply_fn，残差时间从 ~10s 暴增到 350s。
   - **第二版（最终采用）**：存储所有目标态（含空间外），但只存绝对值 >1e-5 的大系数（过滤约 80% 小项）。残差计算不需要重算 apply_fn（350s→25s），内存也可控。同时修复了 H_cols 存 numpy 切片视图导致每块大数组无法释放的**内存泄漏**（改存 `.copy()`），补全了 `del` 临时数组，每块后加 `gc.collect()`。

4. **build_H_incremental 重写（WP2 OOM 根因）**：原 `build_H_incremental` 一次性调用 apply_fn 处理所有 5000 个新增态，输出 2.5 亿项 = 6GB，直接 OOM。重写为和 `build_H_matrix` 一样的分块处理（每块 200 态，240MB，处理完释放），H_cols 同样存拷贝+过滤 |v|>1e-5。**这是 WP2 从来没完整跑完的根本原因。**

**最终验证（5000态×2波包，H₂O/cc-pVTZ）**：

| 波包 | n_var | 能量 (Ha) | H 构建 | 残差 | ||r_out|| |
|---|---:|---:|---:|---:|---:|
| WP1 | 5000 | -76.297894 | 345s | 25.7s | 0.660 |
| WP2 | 9992 | -76.297931 | 403s | 58.8s | 0.658 |

总时间 870s = 14.5min，全程无 OOM，ΔE=3.6e-5 Ha（能量收敛）。注：||r_out|| 几乎不变（0.660→0.658），说明当前波包中心选择策略导致"假收敛"，是后续优化方向。

**程序注析**（`geocore/geoqc/wci.py`）：
- `build_H_matrix`（第 338-445 行）：逐块 apply_fn → 即时 searchsorted 填充 → del 临时数组 → gc.collect()。H_cols[j] 存 `.copy()` 而非视图。
- `build_H_incremental`（第 447-545 行）：完全重写为分块处理，与 build_H_matrix 同构。新增态的 H_cols 同样过滤 |v|>1e-5。
- `h_build_chunk=200`：每块 200 态（~240MB 输出），25 块处理 5000 态。h_build_chunk=1000 实测慢 7.6 倍（kernel 启动开销反而增大）。

### §7.16　优化十三：跳过自旋轨道二体积分 t_s（dim=10¹⁵ 的内存通行证）

**问题。** dim=10¹⁵ 需要 n_orb≈85（n_occ=5）或 n_orb=38（n_occ=8）。自旋轨道二体积分 `t_s` 的大小为 (2·n_orb)⁴ × 16B：

| n_orb | t_s 大小 |
|---:|---:|
| 58 (H₂O/cc-pVTZ) | 6.7GB |
| 85 (dim=10¹⁵, n_occ=5) | **13.4GB** |
| 38 (dim=10¹⁵, n_occ=8) | 2.1GB |

n_orb=85 时 t_s=13.4GB，几乎占满 16GB 系统内存，无法运行。

**关键洞察。** 深入代码分析各函数对 t_s 的依赖：

| 函数 | 是否需要 t_s | 原因 |
|---|---|---|
| `sector_diagonal_at`（one-body 对角） | **否** | 只用 o_s（one-body 自旋轨道积分） |
| GPU 占据感知双激发（`gpu_occ_aware_doubles_sp.py`） | **否** | 直接用空间轨道积分 t（chemist notation），在 kernel 内计算系数 |
| CPU 双激发系数预计算（`exterior.py` 第 1100-1125 行） | **是** | 四重循环预计算所有 (p,q,r,s) 系数 |
| 单激发 apply | **否** | 只用 o_s，二体单激发部分在 GPU doubles 的"准单激发"项中 |

**结论**：当使用 GPU 占据感知双激发时，t_s 完全不需要！CPU 双激发系数预计算是唯一需要 t_s 的代码路径，而 GPU 路径绕过了它。

**实现。** 在 `exterior.py` 的 `sparse_action_sz_vec` 中，将 CPU 双激发系数预计算（第 1100-1125 行的四重循环）包裹在 `if gpu_apply is None:` 条件中。当 `gpu_apply` 不为空时，完全跳过 t_s 预计算，`t_s` 参数可传 `None`。

```python
# exterior.py sparse_action_sz_vec — 关键修改
if gpu_apply is None:
    # CPU 路径：预计算双激发系数（需要 t_s）
    t_s = ...  # (2n)^4 数组
    for p in range(ns):
        for q in range(ns):
            ...
else:
    # GPU 路径：跳过 t_s，双激发系数在 GPU kernel 内实时计算
    t_s = None
```

**内存效果。** n_orb=85 时：
- 修改前：t_s=13.4GB + o_s=0.46MB + 空间积分=398MB → **~13.8GB**（接近 OOM）
- 修改后：o_s=0.46MB + 空间积分=398MB → **~0.4GB**（减少 97%）

**n_orb>64 的位串问题。** 最初尝试 n_orb=85（n_occ=5）时遭遇 `OverflowError: Python int too large to convert to C long`——位串需要 85 位，超过 int64 的 64 位限制。短期解决方案：用 n_occ 更大的系统达到 dim=10¹⁵，保持 n_orb≤64。

| n_occ | 达到 dim≥10¹⁵ 所需 n_orb | C(n_orb,n_occ) |
|---:|---:|---:|
| 5 | >64（不可行） | — |
| 6 | 58 | 4.05×10⁷ |
| 7 | 45 | 4.54×10⁷ |
| **8** | **38** | **4.89×10⁷** |

选择 n_occ=8, n_orb=38（16 电子系统），dim=C(38,8)²=**2.392×10¹⁵**，位串 38 位 < 64，完美适配 int64。

**程序注析**：
- `exterior.py` 第 1100-1130 行：`if gpu_apply is None:` 包裹 CPU 双激发系数预计算。
- 测试脚本 `wci_synth_norb85_test.py`：`o_s = build_spin_orbital_one_body(...)`，`t_s=None`，`hd_fn` 和 `apply_fn` 均传 `t_s=None`。
- 长期方向：支持 n_orb>64 需要将位串从 int64 改为 Python int（object 数组）或多 int64 表示，涉及 RankTable、GPU kernel、exterior.py 等多处修改。

## §8　与 top-k 幂迭代的系统对比

### §8.1　合成系统对比

在 n_orb=6, nelec=6（dim=400）的随机积分合成系统上：

| 方法 | 参数 | 收敛能量 (Ha) | 精确基态 (Ha) | 误差 (Ha) |
|---|---|---:|---:|---:|
| top-k 幂迭代 | k=400, 500 次 | -18.67 | -13.70 | **4.97**（收敛到错误态） |
| WCI | 20 波包, 20 轮 | -13.70 | -13.70 | **2.1e-14** |

top-k 幂迭代收敛到绝对值最大本征值（-18.67）而非基态（-13.70），WCI 由变分原理保证收敛到基态。

### §8.2　真实分子对比

| 系统 | dim | top-k (化学精度 k) | WCI (化学精度波包数) | WCI 变分空间 |
|---|---:|---:|---:|---:|
| H₂/STO-3G | 4 | ~2 † | 1 | 2 (50%) |
| LiH/STO-3G | 225 | 10 (4.4%)* | 4 | 69 (31%) |
| H₂O/STO-3G | 441 | ~100 (23%) † | 5 | 131 (30%) |
| LiH/6-31G | 3025 | 50 (1.7%)* | 10 | 1014 (34%) |

*LiH/STO-3G（k=10）与 LiH/6-31G（k=50）为 **10.87 §6.01/§6.02 直接实测**值（化学精度 7.2e-4）；†H₂/STO-3G 与 H₂O/STO-3G 为按 10.87 经验标度（k/dim ~ 0.13-1.5%）的**外推**（10.87 未直接实测这两个系统）。修正说明：初稿曾将 LiH/STO-3G、LiH/6-31G 误记为 ~50（22%）与 ~500（17%），与 10.87 自报实测不符，已按实测值更正。

**关键差异**：
1. **收敛保证**：WCI 恒收敛到变分基态（变分原理），top-k 幂迭代可能收敛到错误态（无 shift 时；10.87 实测的分子因基态恰为 |λ| 最大本征态而未触发，见 §1.2 调和段）；
2. **空间结构**：WCI 变分空间是 Bruhat 连通的波包并集，top-k 是无结构的幅值截断；
3. **自适应**：WCI 波包数由残差驱动自动选择，top-k 的 k 需人工选择；
4. **标度**：WCI 波包数 ∝ log(dim)（实测 1→10）；top-k 的 k 依 10.87 §6.02 实测**同为亚线性**（k/dim 随规模下降：1.5%→0.13%）——初稿"线性 ∝ dim"表述与 10.87 自报结论矛盾，已更正。但 WCI 的波包数（≤10）远小于 top-k 的 k（H₂O 6-31G 化学精度 k=2000）——注意单位不同：WCI 每个波包含 ~10²-10³ 态（10 波包 = 1014 态），空间大小的诚实对比见第 6 条；
5. **内存**：WCI 构造稠密 H 矩阵（O(n_var²)），top-k 用稀疏 H·v（O(k × 行度)）。WCI 适用于 n_var < ~10000 的系统，更大系统需结合 matrix-free 或选 CI 技术；
6. **诚实的代价**：同达化学精度（能量判据），WCI 的变分空间比 top-k 大——LiH/6-31G：WCI 1014 态（33.5%）vs top-k k=50（1.7%），**约 20 倍**。WCI 以更大的空间换取无谱条件的收敛保证与自适应波包数；这是两种方法的真实权衡，不是 WCI 单方面占优。

## §9　诚实边界与开放问题

### §9.1　已验证范围

1. **波包数 1-6 个**（STO-3G 小基组）和 **化学精度 10 个**（6-31G 中等基组），在四个分子系统上机器验证；
2. **变分收敛性**：能量单调不增，残差为零时精确收敛到 FCI（误差 < 1e-13 Ha）；
3. **性能优化**：三层优化使 LiH/6-31G 总时间 175s → 44s（4 倍），H 矩阵构造 9.8s → 0.4s（24.5 倍）；
4. **dim 标度**：验证到 **dim=2.392×10¹⁵**（H₂CO/cc-pVDZ，n_orb=38, n_occ=8，2026-09-03：5000 态 × 1 波包，8.17 分钟，E=-114.130 Ha，相关能回收率 85%，无 OOM）。此前验证到 dim=29241（LiH cc-pVDZ，2026-09-01：化学精度 ~37 波包；6-31G 的 28-29 波包精确收敛在 cc-pVDZ 上未能复现——见 §9.2 #2），波包数亚线性增长在小/中基组成立、cc-pVDZ 上弱化。dim=10¹⁵ 突破的关键使能器：(a) 占据感知 GPU 双激发（非零项仅 0.44%，计算量减 228 倍）；(b) 跳过自旋轨道二体积分 t_s（13.4GB→0，GPU 路径直接用空间积分）；(c) build_H_matrix / build_H_incremental 分块处理（峰值内存 O(n²) 而非 O(总输出项)）。注：dim=10¹⁵ 验证为单波包 5000 态的可行性与性能标度验证，能量未达化学精度（差 CCSD(T) 0.052 Ha），多波包收敛与化学精度验证见 §9.2 #3。

### §9.2　未验证范围与诚实边界

1. **多参考强相关系统**（N₂ 解离、开壳层、过渡金属）：当前验证的四个系统均为单参考主导或弱多参考（HF% > 90%）。强多参考系统的波包数可能显著增加（10.87 预测 3-5 个，但那是 cc-pVDZ 级单参考系统；强多参考可能需要更多），**未验证**；
2. **更大基组（cc-pVDZ、cc-pVTZ）——已部分验证（2026-09-01 实测）**：LiH cc-pVDZ（19 轨道、4 电子，dim 29241）WCI 实测——**化学精度 ~37 波包**（r_out < 5e-4、E 误差 1.8e-7 Ha），**精确收敛 54+ 波包未完成**（n_var 41.6%+，残差 ~1e-4 且每轮仅降 ~1e-5）——**cc-pVDZ 的精确收敛尾巴极长，波包数远超 6-31G（28-29）**，本文"更大基组波包数增长"的预测被坐实且比预期严重（稠密基组下 Bruhat 球支撑膨胀）。NO 基变换（10.87 §6.05 实测 eff-dim 降 289 倍）是压缩 cc-pVDZ 波包数的关键路径，WCI 的 NO 基选项**仍未实现**；
3. **更大 dim（>10000）**：WCI 构造稠密 H 矩阵（O(n_var²) 内存），n_var > ~10000 时内存和对角化成本过高。需结合 matrix-free 对角化（Lanczos/Davidson）或选 CI 技术，**未实现**；
4. **开壳层系统**：当前实现固定 S_z=0 扇区（n_α=n_β），开壳层（S_z≠0）**未验证**（exterior.py 的 sparse_action_sz 应支持，但 WCI 未测试）；
5. **相对论/自旋轨道耦合**：当前实现仅支持非相对论实积分，复积分（自旋轨道耦合）需用回 complex128，**未实现**。

### §9.3　开放问题

1. **NO 基变换的 WCI 实现**：10.87 §6.05 验证 NO 基使 eff-dim 降 289 倍，若 WCI 在 NO 基下运行，波包数和变分空间大小预计可大幅压缩。需要实现 NO 基积分变换（pyscf 或手写）和 WCI 的 NO 基选项；
2. **增量残差**：当前残差计算每轮做一次全空间 apply_H（占 ~75% 时间），若能复用旧态的 H|ψ⟩ 贡献、只算新增态，预计残差时间可降一个数量级；
3. **波包分裂/合并检测**：多参考系统中，两个波包可能高度重叠（支撑集交集大），合并为一个波包可减少冗余。当前实现不做合并，每个新波包独立添加；
4. **RS-1 预条件**：10.87 §6.04 验证 c_D ≈ -H_DF/ΔE_D（RS-1 微扰系数），若用 RS-1 系数初始化 Rayleigh-Ritz 向量，可加速对角化收敛（但 WCI 用稠密 eigh，不需要迭代，所以 RS-1 预条件主要用于 matrix-free 版本）；
5. **WCI 与 selected CI 的关系**：WCI 本质上是一种几何化的 selected CI（以波包为选择单元而非单个行列式），与传统 selected CI（CIPSI、ASCI）的关系和优劣需要系统对比；
6. **分母加权选择判据（已实测对比，2026-09-01）**：分母加权判据 argmax |⟨D|r⟩|² / |⟨D|H−E|D⟩|（命题 3.03 公式的精确实现，CIPSI PT2 风格）已加入 `geoqc_wci.py`（`--weighted`，完整对角由 `sector_diagonal_sz two_body=True` 提供）。三个系统实测对比：**H₂O/STO-3G（dim 441）**两判据波包中心序列逐位相同；**LiH/6-31G（dim 3025）**与**N₂ STO-3G fc R=3.0（dim 7056，真多参考）**中心序列分别从第 4/5 个波包起分叉，但最终能量一致（差 ≤5.6e-10）、波包数相同（29/40）、最终变分空间差 ≤0.3%。**结论：已测系统上简化判据无性能损失，判据只改收敛路径不改变终点**（变分原理保证）；加权判据的潜在优势（高能大耦合态密集的场景）未在已测系统中出现，若需进一步检验需更大规模/其他类型的多参考系统。
