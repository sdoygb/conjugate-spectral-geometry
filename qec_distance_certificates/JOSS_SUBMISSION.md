# JOSS Submission Plan (status: on hold — resubmit after 2027-02)

## Why we cannot submit yet

JOSS changed its workflow and its pre-review gates (see
`openjournals/joss` repo, `docs/submitting.md`, checked 2026-08-13):

1. **Submission is no longer a GitHub issue.** Issues in
   `openjournals/joss-reviews` are generated by the journal submission
   system. New submissions go through the web form at https://joss.theoj.org
   (requires the submitting author's GitHub OAuth login).
2. **Four pre-review gates**, all required. Our status as of 2026-08-13:

   | Gate | Requirement | Our status |
   |---|---|---|
   | 1. Public development history | Public for **> 6 months**, commits spread across the period | ✗ (public since 2026-08-13) |
   | 2. Demonstrated research impact | Evidence of use in research (papers/preprints referencing it) | ✗ (not yet) |
   | 3. Open source practices | Tests + CI, docs, CONTRIBUTING, tagged releases, changelog | ✓ (added 2026-08-13) |
   | 4. Iterative development | Ongoing iteration, not a single burst | ✗ (single burst so far) |

   JOSS's own wording: a desk rejection on these grounds is a "not yet,"
   rather than a "never."

## Plan

1. **2026-08 — 2027-02 (6-month open-development window)**
   - Keep committing publicly (not one burst): incremental improvements,
     issue tracker usage, releases.
   - Post the accompanying research article (affine-complete RM/CSS codes,
     enumeration-free verification) to arXiv so the package gains a
     "referenced in a preprint" signal.
   - Encourage a colleague to try the package (JOSS asks: "please be sure a
     colleague has tried it").
2. **~2027-02**: submit via https://joss.theoj.org web form (author must log
   in with GitHub). Paper (`paper/paper.md` + `paper/paper.bib`) and the AI
   usage disclosure are already in the repository.

## Immediate alternative: Zenodo DOI

A citable DOI does not require JOSS. Follow GitHub's citable-code guide:

1. Log in at https://zenodo.org with GitHub.
2. Authorize the `sdoygb/qec-distance-certificates` repository.
3. Create a release (or use tag `v0.1.0`): Zenodo archives it and mints a DOI.
4. Add the DOI badge to README.

This can be done today and makes the software citable in the arXiv paper.
